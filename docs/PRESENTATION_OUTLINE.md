# 발표 구성

**한국어** · [English](PRESENTATION_OUTLINE.en.md)

## 10분 발표 구성

1. **문제**: 각자 만든 AI 에이전트 스킬이 개인 컴퓨터에 남아 있어 팀이 함께 평가하고 다시 쓰기 어려움
2. **대상**: 여러 프로젝트와 AI 코딩 도구를 함께 쓰는 개발팀
3. **기존 방식의 빈틈**: 커뮤니티의 인기 순위만으로는 우리 팀 환경에서 쓸 수 있는지 판단하기 어려움
4. **해결 방식**: 필요한 스킬만 팀에 공유하고 동료 평가, 프로젝트 채택, 실행 기록을 함께 관리
5. **차별점**: 일반 Git을 자료 저장소로 사용하고 스킬의 정확한 버전을 프로젝트별로 구성
6. **시스템 구성**: 로컬 스킬 → SkillRoster 클라이언트 → 팀 Git 저장소 → 프로젝트 설치 경로
7. **시연**: `pnpm demo` 또는 실제 원격 Git으로 주요 흐름 확인
8. **오픈소스 활용**: React, Vite, Ajv, simple-git, OpenCode 훅과 자동 라이선스 검사
9. **품질과 운영**: 3개 운영체제 CI, 자동 검사, 실패 복구, Issue 연결형 Pull Request, 공개 Schema
10. **현재 범위와 확장**: 구현된 기능과 다음 단계인 설치형 CLI, 추가 도구 실행 기록, 팀 메모리 구분

## 데모에서 확인할 내용

1. 개요에서 팀원·스킬·프로젝트 현황 확인
2. 스킬 상세에서 작성자 평가와 동료 평가 구분
3. 프로젝트에서 기술 태그와 팀 평가를 참고한 버전 선택
4. OpenCode·Codex·Claude Code 설치 대상 확인
5. YAML 문서와 Git 이력에서 실제 변경 확인

## 한 문장 소개

> SkillRoster는 팀에서 사용하는 AI 에이전트 스킬을 Git에 모으고, 동료 평가와 사용 기록을 참고해 프로젝트별 구성을 만드는 자체 설치형 오픈소스 도구입니다.

## 발표 전 대체 방법

- 인터넷이나 GitHub 인증을 쓸 수 없음: 외부 연결이 필요 없는 `pnpm demo` 사용
- 3210 포트를 이미 사용 중임: 기본 3211 포트를 쓰는 데모 실행
- 브라우저가 자동으로 열리지 않음: 터미널에 표시된 `http://127.0.0.1:3211` 직접 접속
- 화면의 자료 출처 질문: 같은 자료가 YAML과 Git commit으로 남는 모습 제시
- 미구현 기능 질문: [개발 계획](ROADMAP.md)에서 현재 개발본과 후속 범위를 구분해 설명
